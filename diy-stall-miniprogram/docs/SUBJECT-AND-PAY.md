# 小程序主体类型与收款方式说明

## 收款方式（当前实现）

本项目采用 **展示收款码**（微信/支付宝二维码图片），用户在「关于」页长按识别扫码付款。

- **优点**：无需微信支付商户号、无需小程序内接入 `wx.requestPayment`，个人也能快速上线试跑。
- **注意**：资金进入你绑定的收款账户；小程序只做展示，不代扣、不分账。记账仍在管理后台「记账」里手工记录。

上传路径：管理后台 → **图片上传** → 收款码区域。

## 主体类型怎么选

| 阶段 | 建议主体 | 原因 |
|------|----------|------|
| **现在：自己摆摊试用** | **个体工商户**（优先）或继续用 **个人** 测 UI | 个人主体类目与能力受限，且不宜长期商用；个体户成本低，可办 **微信/支付宝商家收款码**，与当前「展示收款码」方案一致。 |
| **中期：稳定出摊、要正规收款与发票** | **个体工商户** | 可注册小程序（企业服务/生活服务类目）、开通 **微信支付商户**（若以后要做在线付定金）；税务、合同相对简单。 |
| **后期：给别人用（多摊位 / SaaS）** | **企业（有限公司）** | 多商户入驻、分账、用户协议、数据合规、ICP/等保等通常需要公司主体；「平台让摊主入驻」在审核上更接近平台类，个人/个体较难通过。 |

### 不推荐长期只用「个人主体」做推广的原因

- 小程序 **微信支付**（用户点按钮付款）个人主体 **无法开通** 商户支付。
- 服务类/商业展示类目审核对个人更严，**代他人运营、多租户** 容易被拒或下架。
- 个人无法做清晰的分账与商户入驻协议。

### 若坚持先零成本试水

- 可用 **个人小程序** + **收款码展示**（本仓库已支持）先验证产品与客流。
- 同时准备注册 **个体户**（很多地区可线上办），把小程序迁到个体户主体下（需重新注册/迁移小程序，提前规划名称）。

## 以后要不要接「小程序微信支付」

| 方式 | 适用 | 复杂度 |
|------|------|--------|
| **展示收款码**（当前） | 现场扫码、客单价低、当面交易 | 低 |
| **小程序微信支付** | 在线付定金、套餐预售、远程下单 | 需商户号 + 类目 + 接口开发 |
| **平台分账**（多摊主） | 别人用你的系统摆摊、你抽成 | 需 **企业** + 服务商/分账产品，合规成本高 |

建议路径：**收款码验证模式** → 个体户 + 商户号（可选在线付）→ 企业化后再做「多摊主入驻」。

## 合规提醒（简要）

- 公园摆摊以当地管理处规定为准，小程序文案避免承诺固定无证经营。
- 展示他人收款码需取得授权；多摊主模式下每个摊主应使用自己的收款主体或走平台分账。
- 收集用户信息（手机号、会员）需隐私政策与用户同意。
